# App

The quiz, progress store, sandbox UI, simulators, pages and routes, testing, and building and deploying. Moved from CLAUDE.md; keep it describing what exists.

- **Quiz** (`src/quiz/`):
  - `grade.ts`: a `Response` is the list of chosen option indexes, for every kind. `grade` is all or nothing; `isAnswered` means exactly `selectCount(item)` picks.
  - `weights.ts`: `TASK_WEIGHTS`, each domain's weight shared among its tasks by objective count (the same split as the bank targets). Practice, readiness and mixed sets weigh by task.
  - `sampler.ts`: `buildMockExam(bank, seen, rng)` takes each domain's `allocateMock()` share, splits it among the domain's tasks by objective count, makes up a short task from the rest of its domain, puts seen items last, and scales the minutes to the real pace when the bank is short. `buildMixedSet` (weighted by task, not pool size), `buildFocusSet` and `orderLeastMastered` (lowest streak first).
  - `results.ts`: `scoreMock` (percent, pass at 48%, rows per domain and per task) and `taskRows`.
  - `ItemView.tsx` renders every kind: a `viz` item draws `<Shelves>` and/or `<Viz>` per `show`. Revealed, it shows each rationale, the explanation, `sourceLinks` and the objectives. `showTask={false}` hides the task name (the mock does). `SessionReview` mounts an item only when its row is opened, so closed rows draw no charts. `shortcuts.ts` (`useShortcuts`), `ShortcutHint`, `ScoreTable`.
- **Progress** (`src/progress/`): `store.ts` (version 6; its rules are in CLAUDE.md) keeps item stats with a streak, mock results, sandbox challenge completions (`sandbox`: id → first solve time), `lessonsRead`, calc exercise completions (`calcExercises`) and saved calcs (`calcs`: `{source, name, formula, savedAt}`, unique per source and name), flashcard review state (`flashcards`: card id → `{box, due, lastAt}`) and own decks (`decks`: `{id, name, cards: {id, front, back}[], createdAt}`; card ids `my-<uuid>`, and removing a card or deck drops its review state) and Tableau Public challenges (`challenges`: id → `{steps, checkpoints}`, the ticked step ids and the correctly answered checkpoint ids), with export and import. `migrate()` upgrades v1–v5 data both on load and on import. `readiness.ts`: `taskReadiness` (coverage × accuracy), `weightedReadiness`, `weakSpotItems` (the 3 weakest tasks) and `masteryOf`/`MASTERY_LEVELS`.
- **Sandbox** (`src/build/`): the free sandbox (`SandboxPage`) has tabs Sheet 1, Sheet 2 and Dashboard 1 over a workbook in the hash (`engine/dashboard.ts`); each sheet tab is a `Sandbox`, and `Dashboard.tsx` draws both sheets in the layout container with a Use as Filter button per sheet, the selection line (with a link per Menu action) and Dashboard ▸ Actions (the list, Add Action ▸ Filter…, and the action's Name, Source sheet, Run action on, Target sheet, Clearing the selection will and Target filters). Action states live in the component, not the hash. `Sandbox.tsx` (Filters, Marks card, Columns/Rows, the view with the marks selection bar (Group, Create Set), and the open dialog; it edits a spec the page owns), `DataPane.tsx` (fields by role, hierarchies as trees, field menus; a dimension dropped on a dimension adds it to that one's hierarchy or starts a new one), `DerivedEditors.tsx` (Group, Set with General/Condition/Top tabs, Bins, Create Hierarchy), `ShelfPill.tsx` (pill and its menu, the drill +/− button, Show In/Out of Set or Members in Set, Dual Axis and Synchronize Axis on a shelf with two measures, and on a measure in the view Quick Table Calculation, Compute Using and Clear Table Calculation, with a △ on the pill); an Analysis row above Columns holds the Totals menu (Show Row/Column Grand Totals, Add All Subtotals, Total All Using) and a chip per reference item (Edit…, Remove). The side pane has Data and Analytics tabs: `AnalyticsPane.tsx` lists Constant Line, Average Line, Median with Quartiles, Totals and the custom Reference Line, Reference Band and Distribution Band; each is dragged onto the view (then `DropTargets` asks for Table, Pane or Cell, per measure or for all) or picked from its menu. `RefEditor.tsx` is the reference line, band and distribution dialog (axis, scope, value or computation, label); the Marks card shows a tab per measure (All, then each) when a shelf holds several, and the Measure Values card appears when it's in use; a measure's Data pane menu offers Drop on the Columns/Rows axis, `FilterEditor.tsx`, `SortEditor.tsx` (members, field or Manual with Move up/down; for a pill or, with `scope="default"`, Default Properties > Sort), `FieldEditors.tsx` (Rename, Aliases, Comment, Number Format dialogs), `members.ts` (`useMembers`, `manualKey`), `Menu.tsx` (accessible menu button: arrow keys, Escape, focus return), `dnd.ts` (HTML5 drag and drop of fields, pills and Analytics items; every drag also has a menu path, which the tests use: the field menu's Add to …, the pill menu's Move to …, Move earlier/later (`reorderPill`) and Remove, the Analytics items' menus). Below `lg` the Data pane scrolls in its own box. `CalcEditor.tsx` (name, formula, live `CalcStatus` with the error span marked and a lesson link, field and function lists that insert at the cursor; `calcStatus()` compiles a formula on a sheet) is shared by the playground and the sandbox's calc dialog. The Data pane lists the sheet's calcs (`=` icon), creates and edits them, and adds saved ones; applying a calc there also saves it. Each base field's menu has the lesson 1.3/4.2 actions (Rename, Aliases, Convert to Dimension/Measure and Discrete/Continuous, Create Group/Set/Bins, Change Data Type, Geographic Role, Default Properties: Comment, Number Format, Sort, Aggregation), every dimension's has Create/Add to/Remove from Hierarchy, and a sandbox-only "Undo all changes to this field"; the comment shows as the field's tooltip.
- **Simulators** (`src/sims/`, PLAN.md §7c): one component per simulator, its copy in `src/content/sims/<id>.json` (`sims.ts`: `id`, `title`, `summary`, `objectives`, `intro`, keyed `copy`, 2–3 closing bank `items`; `SIM_ORDER`). `sims/index.ts` registers each as a lazy chunk; every module exports `COPY_KEYS`, and `content/sims.test.ts` checks the JSON has exactly those keys and that the items exist and test the sim's objectives. `Choice.tsx` is the shared toggle-button group. Group, set or hierarchy? links each answer (but parameters) to its result built on the Driftlight data in the sandbox (`PRESETS`, drawn in `groupSet.test.ts`). Granularity and Blue vs. green draw with the engine (`<Viz>`, and `runQuery` from `engine/runtime.ts` for mark counts); `sims.test.ts` draws every state they can reach. Live vs. extract, Data model lab, Filter order, Group/set/hierarchy and Dashboard actions run on small invented sample tables inside the component (the UI says so), with their logic in exported pure functions tested in `<name>.test.ts`. Render copy that may hold backticks through `Inline`.
- **Tableau Public challenges** (`src/challenges/`): `answer.ts` (`answerMatches`: a member compares without case; a number may be typed with separators, a trailing %, or a K/M/B suffix, and matches within half a unit of the last digit either side gives, never more than 1% off; `challengeStatus`: done when every required step is ticked and every checkpoint answered), `components.tsx` (the MDX components: `Step` with its checkbox and an optional badge, `Checkpoint` with Check and Show the answer, `DataFiles` linking `BASE_URL`/`data/<file>`, and the lessons' `Callout` and router-aware links).
- `src/components/Inline.tsx` renders `` `backtick` `` spans in stems, options and rationales as code.
- `src/app/`: `routes.tsx` (every page lazy-loaded; keep content imports out of it and `Layout`) and `Layout.tsx` (nav grouped into Learn, Quiz and Build dropdowns plus Progress, a phone Menu button that lists every group, the non-affiliation footer).
- `src/pages/`:
  - `HomePage` (the exam in one line, a card per pillar, the guides, and the outline as one collapsible section per domain with its tasks linked to their lessons).
  - `LearnPage` (`/learn` grouped by domain in guide order, with read marks; `/learn/:taskId` with the tl;dr, objectives, sources, Mark as read and previous/next in guide order). Revealed items link to their lesson.
  - `PracticePage` (`?task=`, `?domain=`, `?mix=N`, `&focus=1` for least mastered, `?weak=1`).
  - `QuestionsPage` (`/questions` with topic, kind and mastery filters in the URL; `/questions/:itemId`).
  - `MockExamPage` (countdown, flags, review screen, results by domain and task).
  - `ProgressPage` (readiness by domain, weakest tasks, export and import).
  - `CalcPage` (`/build/calc`: source, examples, the editor, a preview of the values, save, Open in sandbox, saved calcs and the exercise list; `/build/calc/:exerciseId`: prompt, Check, hints, Show an answer, debrief, next link). `calcPage.test.tsx` mocks `engine/calc/runtime`. Lessons' `BuildLinks` list the calc exercises for their task.
  - `SimPage` (`/build/sim/:simId`: intro, objectives, the sim, then its closing items answered in place and recorded like practice answers, and lesson links). Lessons' `BuildLinks` list the simulators for their task. `simPage.test.tsx` mocks `engine/runtime`.
  - `FlashcardsPage` (`/flashcards`: built-in cards by task with due/new counts, own decks with import/export; `?task=`, `?all=1` or `?deck=` starts a session of due cards then up to 20 new ones, in learning order, with Space and 1/2/3; `/flashcards/deck/:deckId` (`new` to create) edits an own deck). Lessons' `BuildLinks` link the task's cards. `flashcardsPage.test.tsx`.
  - `ChallengePage` (`/build/challenges/:challengeId`: summary, lesson link, status line, the MDX, objectives, sources, next link). Lessons' `BuildLinks` list the task's challenges.
  - `SandboxPage`'s free sandbox reads `#spec=` links as Sheet 1 and writes `#wb=` once Sheet 2 or the dashboard is used.
  - `BuildPage` (`/build`: sandbox and calc playground links, Tableau Public and sandbox challenge lists with done marks) and `SandboxPage` (`/build/sandbox` free, with the spec in `#spec=` and Undo; `/build/sandbox/:challengeId` with target, Check, hints, debrief, next link). `sandboxPages.test.tsx` mocks `engine/runtime`.
  - `pages.test.tsx` renders real routes with `createMemoryRouter` and an async `renderAt()`. `quizPages.test.tsx` runs the quiz pages over a `vi.mock`ed bank built from `fakeBank()`/`fakeItem()` in `src/test/fixtures.ts`.
- Theme tokens (`src/index.css`, `@theme`): `brand`, `brand-dark`, `accent`, `chalk`, `page`, `header`, and the pill colours `discrete` (blue) and `continuous` (green). Dark mode follows the OS by remapping the tokens and the slate scale once, so components don't use `dark:` variants.

## Tests, production builds and deploy

Tests run in Node by default. Component tests start with `// @vitest-environment jsdom`. Vitest runs without globals, so `src/test/setup.ts` registers Testing Library's `cleanup`.

To check a production build in a browser, run `BASE_PATH=/Tableau-DF_prep/ npm run build`, then `BASE_PATH=/Tableau-DF_prep/ npx vite preview`. Preview also reads `base` from `BASE_PATH`; without it, asset requests under the sub-path fall back to `index.html` and the page stays blank. Headless Chrome needs `--virtual-time-budget=30000` to wait for the lazy pages and the dataset.

GitHub Pages serves the app under `/Tableau-DF_prep/`. `.github/workflows/deploy.yml` runs lint, the tests and `BASE_PATH=/Tableau-DF_prep/ npm run build`, copies `index.html` to `404.html` so deep links work, and deploys on push to `main`. Vite's `base` and the router's `basename` come from `BASE_PATH`, so use router `Link`s, never root-relative `<a href="/…">`.
