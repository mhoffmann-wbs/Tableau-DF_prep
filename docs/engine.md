# Engine and dataset

The chart engine (`src/engine/`) and the Driftlight dataset (`src/data/`). Moved from CLAUDE.md; keep it describing what exists.

- **Engine** (`src/engine/`). Engine modules import each other with `.ts` extensions, so scripts can use them.
  - `spec.ts`: the viz spec.
    - `source` is `sessions` (default), `subscribers` or `titles`.
    - `calcs`: the sheet's calculated fields `{name, formula}`, kept in the spec so `#spec=` links stay self-contained. Pills, filters and sorts name them like any field.
    - `fields`: Data pane edits of the source's fields, `{field (data source name), name?, type?, geo? (null removes), role?, as?, aliases?, agg?, format?, sort?, comment?}`, also kept in the spec. Everything else names a field by its current name.
    - `groups` (`{name, field, groups: {name, members}[], other?}`), `sets` (`{name, field, fixed?, rule}`; rule `members` (General tab or from marks, optionally `exclude`), `condition` (`{field, agg, op, value}`) or `top` (`{from, n, field, agg}`)), `bins` (`{name, field, size}`) and `hierarchies` (`{name, fields}`, general to detailed; a field is in one at most). Group and set members are underlying members' display strings.
    - `columns`/`rows` hold pills. The Marks card has `type`, `color`, `size`, `label`, `shape`, `detail[]` and `tooltip[]`.
    - `filters`: `values` (members by display string, optionally `exclude`), `range` (row-level, or a measure filter after aggregation when `agg` is set), `dateRange` and `datePart` (canonical numbers).
    - `measureValues`: the Measure Values card (pills), which the generated fields `Measure Names` and `Measure Values` (`MEASURE_NAMES`, `MEASURE_VALUES`) stand for. `axes: {columns?, rows?: {dual?, sync?}}`: Dual Axis on the shelf's two measures, and Synchronize Axis.
    - `refs`: reference items from the Analytics pane, each `{kind: line|band|distribution, measure (a pill on an axis), scope: table|pane|cell, label: none|value|computation|custom, custom?}` with a line's `value`, a band's `from`/`to` (`{kind: constant, value}` or `{kind: computed, agg}`, `REF_AGGS`) or a distribution's `dist` (percentages of a computation, percentiles, quantiles 3–10, standard deviation with factor and sample/population).
    - `totals: {row?, column?, subtotals?, using?}`: Analysis > Totals. Row Grand Totals add a `Grand Total` member across (Columns), Column Grand Totals one down (Rows), subtotals a `Total` member under each outer header; `using` is Total All Using (`automatic` aggregates the underlying rows, `sum|avg|min|max` the marks).
    - A pill is `{field, agg?, date?: {level, mode: part|value}, as?: discrete|continuous, sort?: {order, field?+agg? (computed), manual?}, mark?, setView?, tableCalc?: {type, compute?}}`; `mark` is a measure's own mark type when its shelf holds several measures (its own Marks card). `weekday` can only be a part. Filters and manual sorts hold underlying members, before aliases. A set pill shows In/Out, or with `setView: 'members'` the members In the set. `tableCalc` is a quick table calculation on a measure (`TABLE_CALCS`; `compute` is one of `COMPUTE_USING`, else the default for the view).
  - `model.ts`: the field metadata (the dataset after preparation: Postal Code is a geo string, Release Year a discrete dimension, and Latitude/Longitude are measures with an AVG default) and `SOURCE_INFO` (fields in Data pane order, a `<Source> (Count)` measure, and `Latitude/Longitude (generated)`).
    - `buildDataset(csvTexts)` builds three flattened sources. Each base table is left-joined many-to-one to its lookups, so rows never multiply, and unmatched lookups become nulls. Sessions get titles, subscribers, plans and regions; subscribers get plans, regions and cancellations.
    - Values are typed: dates are UTC epoch ms and empty cells are null. `loadDataset()` fetches `public/data/` once in the browser.
    - Field edits: `fieldsOf` applies `spec.fields` before compiling calcs, so formulas see renamed fields; an edited field carries `original {name, type}`, and `calcsOf(ref).read` maps it to its column and converts the value (`convertValue`; `TYPE_CHANGES` lists the type changes offered, where the help's "Text is treated as Null" rules give the result). `isEditable` excludes calcs, groups, sets, bins, `(Count)` and generated fields.
    - Groups, sets and bins (`Field.derived`) are dimensions built on the edited source fields (never on calcs, and calcs can't use them); one with a missing or unfit field stays in the list with `broken`, and its pills turn red. `read` gives a group's name (or Other, or the member itself), a set's `In`/`Out` and a bin's lower limit (`binOf`, lower limit inclusive). `calcsOf(ref, rows)` takes the source's rows for sets with a condition or top rule, computed per member over the whole source (so filters don't change membership). `sheetOf(ref)` is the part of a spec that decides its fields.
    - Calculated fields: functions that take a field's source accept a `SourceRef` (a `SourceId`, or a spec-like `{source, calcs, fields}`); pass the spec wherever calcs or field edits may matter. `fieldsOf(ref)`/`fieldOf(ref, name)` add the compiled calcs (cached): a number calc is a measure (SUM), an aggregate calc a measure without a default aggregation (`AGG(…)`, `ResolvedPill.agg === 'agg'`), anything else a dimension. `calcFields()` keeps a broken calc in the list with `calc.error`, so the Data pane shows it and pills on it turn red. A calc may use the fields and the earlier calcs, never `(Count)` or generated fields.
  - `pills.ts`: `resolvePill` decides dimension or measure, blue or green, and the Tableau label (`SUM(…)`, `CNTD(…)`, `MONTH(…)`). It throws `EngineError`, which carries learner-facing messages.
    - Date dimensions default to the YEAR part (a YEAR value once the field is converted to continuous); a field's `as` sets the default continuity.
    - Aggregated numbers and COUNT/COUNTD are continuous, and MIN/MAX/ATTR of non-numbers are discrete.
    - Measure Names is a discrete dimension and Measure Values a measure without an aggregation of its own (`agg: 'agg'`, like an aggregate calc); neither can be aggregated, used in formulas or edited (`Field.special`).
  - `values.ts`: date parts and truncations (UTC, weeks start on Sunday), `display`, `compareKeys`, `aggregate`, and `formatNumber`/`formatExpr` (a field's number format in JS and as a Vega expression), shared by the query layer and the calc evaluator (`query.ts` re-exports them).
  - `calc/`: the calc subset (PLAN.md §7b), data-free except `run.ts`/`runtime.ts`.
    - `syntax.ts` tokenizes and parses (the help's precedence table; `CalcError` has `kind` syntax|field|type|mix, a `span` and an optional `explain`). `check.ts` gives every node a type and a level (row, agg, const) and throws Tableau's verified message `MIX_MESSAGE` ("Cannot mix aggregate and non-aggregate arguments with this function.") when they mix. `functions.ts` holds the function table (syntax, summary and an example from the help, type rule, implementation) and the date helpers; `evaluate.ts` runs a node in a row scope or a group scope. Null and divide-by-zero rules follow the help and the Tableau KB; where the help is silent (ROUND halves, SPLIT out of range, CONTAINS case, month-end DATEADD, `/` on integers), the code says so and no exercise depends on it. `TODAY()` is pinned to `CALC_TODAY`.
    - `index.ts`: `compileFormula`, `rowValue`, `evaluateRow`, `evaluateGroup`. `run.ts`: `previewCalc` (sample rows, or one row per member for an aggregate calc) and `checkCalc` (compares a formula with a reference over every row, or per member of the exercise's `by`, and phrases the first difference). `runtime.ts` is the playground's lazy chunk (dataset, no Vega).
    - `calc.test.ts` runs the help's examples, the null rules, precedence, the errors, and calcs in queries against plain reductions.
  - `query.ts` (`query(spec, dataset)`) runs: row filters → one group per combination of the view's dimension members → aggregation → measure filters → member order. Results are `{columns, rows}`, keyed `c0, c1…`.
    - Discrete members are display strings (`Q3`, `January`, `Null`, `True`). Continuous dates are epoch ms.
    - Each discrete column carries its member `order`: the natural order (date parts chronologically, strings alphabetically, Null last), a computed sort, or a manual one; a pill's sort wins over the field's default sort. Aliases apply last: `order` and the rows hold the aliases, `raw` the underlying members.
    - Generated coordinates come from the finest geographic dimension in the view, using `data/geography.ts`.
    - With Measure Names or Measure Values in the view, each mark also computes the Measure Values card's measures (less those a Measure Names filter leaves out), and the rows unpivot: one per mark and measure, Measure Names ordered as the card.
    - `columnOf(result, source, pill)` reads a pill's column. Use it in tests and checkpoints instead of assuming column order, because columns follow `pillsOf` order: Columns, Rows, then the Marks card.
  - `tablecalc.ts`: quick table calculations. `addressing(compute, across, down)` gives the dimensions Compute Using runs along, slowest first (the innermost of each shelf is the one inside a pane); the others partition. `defaultCompute` (across when Columns has a dimension, else down) and the formulas the help doesn't give are marked unverified there. `tableCalcValues(type, values)` computes one partition. The query runs them after measure filters and member order, gives the column its own key, a `<Calc> of <label>` title and, for shares and rates, a percent format.
  - `refs.ts`: `refValues(ref, values, total, measure)` gives a reference item's lines (with labels; a band's edges carry only labels) and shaded range over the marks in one scope; Total uses the scope's underlying rows. Percentiles and quantiles use R's type 7 (`quantile`), as the help says. The query's `refsOf` groups the view's marks (not totals) by scope: Table is one group, Pane the shelves' outer dimensions, Cell those plus the innermost discrete ones; it returns `QueryResult.refs` (`{index, column, scope, scopes: {members, lines, band?}[]}`) and skips items whose measure isn't a continuous measure in the view.
  - Totals (`totalsOf` in `query.ts`) are extra marks after the view's marks: a shelf with no discrete dimension or with a continuous one gets none, and a table calculation's total is null.
  - `render.ts` (`toVegaLite`):
    - The innermost pill on a shelf becomes the axis (continuous) or the band (discrete). The discrete pills before it become facet panes, several joined with " · ". Several continuous pills at the end of one shelf (one shelf only) become measure panes: the measures fold into `__v` with a `__m` pane each and independent scales, one layer per mark type. With `axes[shelf].dual` the two measures layer in one pane with an axis each (independent scales, or shared when synchronized), coloured from `DUAL_COLORS` when Color is empty.
    - `automaticMark` follows Tableau's Automatic (the help's rules, lesson 2.1/3.1): geo → circle, nothing continuous → text ("Abc" without a label), a date field (part or value) with a measure → line, measure × measure → shape, a continuous dimension × measure → circle (no documented rule), otherwise bar. Each measure's mark is its own `mark`, else the Marks card's, else Automatic's for its pair of axes.
    - A continuous number column whose field has a `format` gets a `labelExpr` axis and `<id>f` text columns for tooltips and labels.
    - Reference items join the data as rows marked `__ref` (one per pane they reach, so facets place them), which the mark layers filter out. Each draws on its measure's axis: shading behind the marks (`rect`), then a dashed `rule` (a `tick` across the band when per cell) and a label. On a dual axis a measure's reference layers nest with its own layers so they share its scale.
    - `square` on two discrete shelves becomes a highlight-table `rect`. `density` uses translucent circles. `map` draws a filled country map via a lookup on world-atlas ISO ids; lat/long marks draw on an `equalEarth` world.
    - Band width comes from the longest label. Charts take colours from a `Theme`. `needsWorld(spec)` says whether to load the topology.
  - `edit.ts`: pure spec edits for the sandbox (`placePill`, `movePill`, `removePill`, `replacePill`, filters, mark type), the pill-menu rules (`aggregationChoices`, `withAggregation`, `withDateLevel`, `canToggleContinuity`, `withContinuity`), `defaultFilter`, and the `#spec=` hash (`specHash` writes it without defaults, `parseSpecHash` reads it). Shelves are addressed as `PillAt {shelf, index}`; Color/Size/Label/Shape hold one pill, so a drop replaces. `setCalc` adds or replaces a calc (a rename follows through pills, filters, sorts and formulas), `removeCalc` takes its pills and filters with it. `editField(spec, original, patch)` changes a field (`undefined` keys go back to the source; a rename follows through like a calc's and throws `EngineError` on a taken name; a new type clears the field's filters and its pills' date levels and sorts), `resetField` undoes all of it. `combineOnAxis(spec, shelf, field)` drops a measure on a shelf's axis (Measure Values on the shelf, both measures on the card, Measure Names on Color when free); `setDualAxis`, `setSyncAxis`, `setPillMark`, `continuousOn`. Table calcs and totals: `canTableCalc`, `withTableCalc` (undefined clears), `withComputeUsing`, `computeUsingOf`, `setTotals`. Reference items: `axisMeasures`, `setRef` (adds when `index` is undefined), `removeRef`. The Measure Values card is a list shelf (`measureValues`). `setDerived(spec, 'groups'|'sets'|'bins', index?, def)` adds or replaces one (a rename follows through; a taken name throws), `removeDerived` takes its pills, filters and hierarchy place with it. Hierarchies: `createHierarchy`, `addToHierarchy`, `removeFromHierarchy`, `removeHierarchy`, and drilling on a list-shelf pill (`drillState`, `drillDown` puts the next level right after it, `drillUp` removes the levels below).
  - `dashboard.ts`: the free sandbox's workbook (`workbookSchema`: two `sheets` and a `dashboard` with a `layout`, horizontal or vertical, and filter `actions`: `{name, source, target, run: hover|select|menu, clearing: leave|all|exclude, fields? (Selected fields), useAsFilter?}`). `nextActionState` applies a selection or the clearing option; `actionFilters`/`filteredSheet` turn an action's state into `values` filters on the target (per field, the selected marks' members, only on discrete non-date dimensions of the source view (`viewDimensions`) that the target's source has by name), or `excluded`. `toggleUseAsFilter` adds or removes a Select / Show all values action to the other sheet. `workbookHash` writes `#spec=` while only Sheet 1 is in use, else `#wb=`; `parseWorkbookHash` reads it.
  - `match.ts`: `matchSpec(spec, accepted[])` for challenges, data-free. Pills compare by resolved key; once the shelves agree, the mark by its effective type per measure (own, sheet's, or Automatic for its axes) and Dual/Synchronize Axis; also the Measure Values card in order, reference items without their labels, totals, and the calcs (formula without spaces or case), groups (which members go together), sets and bins the target defines, by name. Detail is unordered, Tooltip ignored, filters compare as sets, sorts only where the target has one. Hints come from the closest accepted spec.
  - `runtime.ts`: a lazy chunk with the dataset, query, vega-embed and world-atlas. `membersOf(source, pill)` lists members for the filter, alias and manual-sort dialogs: labels with aliases, values underlying (date parts carry their canonical number, via `partFromLabel` in `query.ts`). It uses only `sheetOf(spec)`, never its shelves or filters. `renderViz(el, spec, theme, onMark?, onHover?)` reports a clicked mark's discrete dimension members (underlying values) for groups and sets made from marks and for dashboard actions, and with `onHover` the members of the mark under the pointer (an empty list on leaving it); `<Viz onMark onHover>` passes them through. `Viz.tsx` imports it on first draw, keys its state by the spec's JSON, and shows `EngineError` messages. `Shelves.tsx` and `PillChip` show a spec's shelves read-only and need no data.
  - Tests: `src/test/dataset.ts` gives `testDataset()` (the committed CSVs) and `referenceData()` (the generator's typed rows, the independent reference). `query.test.ts` checks the engine against plain reductions over the reference. `render.test.ts` compiles every chart type with Vega-Lite and renders it to SVG in Node (`new View(parse(compile(vl).spec), {renderer: 'none'}).toSVG()`).
  - `src/pages/ChartGalleryPage.tsx` (`/dev/charts`, not in the nav) shows each basic chart type from the outline with its shelves. Use it to check rendering in a browser.
- **Dataset** (`src/data/`):
  - `generate.ts` builds the Driftlight dataset from `SEED`: 3,000 subscribers, 4 plans, 400 titles, 15k sessions in 2024 and 17k in 2025, about 400 cancellations, 25 countries in 5 regions, and monthly targets by region. It returns the file contents plus the typed rows.
  - `scripts/generate-data.ts` writes the files to `public/data/` (committed, served for download). Changing the generator moves every number the content cites.
  - `data.test.ts` fails if the committed files differ byte for byte from the generator. It also checks consistency (sessions only by active subscribers, of released titles) and the deliberate quirks:
    - ZIP codes with a leading zero
    - city spelling variants (München/Munich, Köln, Sao Paulo, Bogota)
    - a few null `Minutes Watched` and blank `Device` values
    - union-compatible session files
  - `xlsx.ts` is a minimal deterministic `.xlsx` writer (fflate, fixed local-time mtime) for `targets.xlsx`. Monthly dates are stored as real Excel dates.
  - `rng.ts` holds `seededRng` (mulberry32), `pick`, `weighted`, `randInt`, `shuffle` and `sessionRng()` (a generator seeded from `crypto`, one per practice session or mock). Never use `Math.random` for content or samplers: samplers take an `Rng`, and tests pass a fixed seed.
- `src/data/geography.ts`: the regions, countries (with ISO numeric ids for world-atlas) and cities with coordinates. Both the generator and the engine use it.
