## Big idea

Raw data arrives with column names, codes and types chosen for the system that produced it, not for the people reading your dashboard. Task 1.3 is about fixing that **inside Tableau**, as metadata, without touching the source:

- **Rename** a field: `cust_sgnup_dt` becomes Signup Date.
- **Alias** its members: plan code `PRM` shows as Premium.
- **Assign a geographic role**: Country becomes something Tableau can put on a map.
- **Change the data type**: a postal code read as a number becomes a string.
- **Set default properties**: Monthly Price always shows as currency.

In pandas terms, these are the `rename`, `map`, `astype` and formatting steps you'd write at the top of a notebook, except that Tableau stores them in the workbook or `.tds` (task 1.1) and applies them to every view.

## How it works

### Rename a data field

"You can rename fields in the Data pane." Select the field and press **F2** (or click and hold the name until it becomes editable, or right-click and choose **Rename**), type the new name and press Enter.

- "Renaming a field doesn't change the name of the field in the underlying data source, only what appears in Tableau."
- "The changed field name is saved with the workbook and when you export the data source."
- To undo it, click the small circular arrow at the right of the edit box "to restore the original data source field name". For several fields at once, select them, right-click and choose **Reset Names**.

### Assign an alias to a data value

An **alias** renames a **member** (a value), not the field: "You can create aliases (alternate names) for members in a dimension so that their labels appear differently in the view." Driftlight's plans arrive as codes. Premium subscribers sit under `PRM`, all <Fact id="prm-count" /> of them:

<LessonViz id="plan-codes" />

"In the Data pane, right-click a dimension and select **Aliases**." In the dialog, type the new label next to each member, such as Premium next to `PRM`. **Clear Aliases** sets the members back to their original names.

The rules the exam checks:
- "Aliases can be created for the members of discrete dimensions only. They can't be created for continuous dimensions, dates, or measures."
- "Tableau doesn't permit re-aliasing measures because it involves modifying data values themselves."
- "When using a published data source, you can't create or edit aliases."

An alias is a display label for one member. To merge two members into one, such as two spellings of a city, you need a **group** (task 2.2), not an alias.

### Assign a geographic role to a data field

"In the Data pane, click the data type icon next to the field, select **Geographic Role**, and then select the geographic role you want to assign to the field." The roles include Airport, Area Code (US), CBSA/MSA (US), City, Congressional District (US), Country/Region, County, NUTS Europe, Latitude, Longitude, State/Province and ZIP Code/Postcode. The Latitude and Longitude roles are "only available for numeric fields".

What the role does:
- The field's icon becomes a globe ("geographic values (used with maps)").
- "Tableau adds two fields to the measures area of the Data pane: Latitude (generated) and Longitude (generated)."
- "Tableau creates a map view when you add the field to Detail on the Marks card."

**Unknown locations.** If Tableau can't match some values, "those values are marked as unknown in the lower right corner of the map view". Click that indicator and choose **Edit Locations** (or use **Map > Edit Locations**). There you can add a Country or State field to remove ambiguity (Paris, France vs. Paris, Texas), match unrecognized values to known ones, or enter latitude and longitude yourself.

### Change the data type for a data field

Every field has a data type, shown by its icon: text (string), date, date & time, number (whole or decimal), Boolean (true/false), and geographic values for fields with a geographic role. To change it:
- on the **Data Source page**, "click the data type icon for the field" in the grid and choose from the list
- in the **Data pane**, "click the icon to the left of the field name, and then choose a new data type from the drop-down list"
- in a view, right-click the field and choose **Change Data Type**.

Why it matters:
- A **postal code** read as a number would lose its leading zero: Newark's `07106` would become `7106`, and Tableau would offer to add the codes up. Make such codes strings (and give them the ZIP Code/Postcode role).
- In a column with mixed values from a file, a number type treats text as Null: "Numbers: Text is treated as Null."
- Change types before you build an extract: "Be sure to change data types before you create an extract."

### Change default properties for a data field

Right-click a field in the Data pane and open **Default Properties**. "The Default Properties menu includes default settings for aggregation, comments, number formatting, color, shape, and totals (based on the type of field)":

| Default property | For | What it sets |
|---|---|---|
| **Comment** | Any field | A note shown in the field's tooltip in the Data pane |
| **Color** | Dimensions | The colour of each member whenever the field is on Color |
| **Shape** | Dimensions | The shape of each member whenever the field is on Shape |
| **Sort** | Dimensions | The default member order, which "also controls how the field values are listed in a filter" |
| **Number Format** | Numbers | For example currency with two decimals |
| **Date Format** | Dates | For example `yyyy-mm-dd` |
| **Aggregation** | Measures | The aggregation "used automatically when the measure is first totaled in the view" (task 4.3) |

Defaults apply when you drag the field into a view: "The fields and their marks are displayed initially based on their default settings." Formatting a single pill or view changes only that view. Colour defaults are shared: "Color encodings are shared across multiple worksheets that use the same data source."

## Exam traps

<Callout title="Rename vs. alias">
  <p>Rename changes a field's name (Signup Date). An alias changes how a member is displayed (PRM shows as Premium). Neither changes the underlying data.</p>
</Callout>

<Callout title="No aliases for measures, dates or continuous fields">
  <p>Aliases work only on members of discrete dimensions. An option that aliases a measure value or a date is wrong.</p>
</Callout>

<Callout title="Geographic role comes from the data type icon">
  <p>The geographic role sits in the same menu as the data type: click the field's data type icon in the Data pane. It generates Latitude (generated) and Longitude (generated) as measures. Unmatched values appear as "unknown" and are fixed with Edit Locations.</p>
</Callout>

<Callout title="Default property vs. format in one view">
  <p>To make every future view show a field the same way (currency, a colour palette, an aggregation), set a Default Property in the Data pane. Formatting a pill on a shelf affects only that sheet.</p>
</Callout>

<Callout title="Superstore note">
  <p>Superstore's Postal Code is the classic example of a field that should be a string with the ZIP Code/Postcode role, and Country, State, City and Region are the classic geographic fields.</p>
</Callout>
