## Purpose

**Tableau-DF_prep** is a self-study web app for the **Salesforce Certified Tableau Desktop Foundations** exam (Analytics-101). It is written in English for data bootcamp learners who know spreadsheets and some SQL or Python but little or no Tableau. It has three pillars:
- **Learn**: one lesson per task (12).
- **Check**: practice, the question bank and a mock exam of 40 items in 70 minutes, passing at 48%.
- **Build**: a Tableau-style viz builder sandbox, a calculated-field playground, concept simulators, Tableau Public challenges and flashcards. These replace a coding lab, because the exam has no hands-on items.

Every scenario uses one invented streaming service, **Driftlight**, and its generated dataset.

## Rules that span the codebase

- **Content is data.** Lessons, questions, calc exercises, challenges and flashcards are files under `src/content/`, validated with Zod and rendered generically. To add content, add data, not a component. The exception is the simulators, which are components, though their copy is data.
- **One engine.** `src/engine/` (data model, query layer, calc evaluator, Vega-Lite renderer) is shared by the sandbox, `viz` items, lesson embeds, simulators and challenge checkpoints. Don't build a second chart path.
- **Numbers come from the data.** Any value an item, lesson or checkpoint states about the Driftlight data is declared as an engine query and checked in a test, never typed by hand.
- **Tableau editions**: the challenges target Tableau Desktop Public Edition. Where Public can't teach an objective, an optional step may use the free Desktop Free Edition. The exam itself assumes the paid Desktop.
- **Tableau facts are never written from memory.** Menu paths, defaults and the differences between Tableau Public and Desktop are checked against the docs. `PUBLIC_LIMITS` entries are `documented` (with a help.tableau.com source) or `unverified`.
- Draw the Tableau UI as schematic diagrams in our own style. Never use Tableau screenshots or copy its visual design. Don't redistribute Sample-Superstore: Superstore is mentioned in notes only.
- Write every question for this app. Never reproduce live exam content or third-party question dumps.
- The app is static: no backend, no accounts. Keep Vega-Lite and the engine lazy-loaded.
- `src/progress/store.ts` is the only module that touches `localStorage`. It is versioned: bump `VERSION`, add a migration in `load()` and keep the Zod `ProgressSchema` (used to validate imports) in step when the shape changes.

## Commands

```bash
npm run dev               # Vite dev server
npm run build             # tsc -b + production build
npm run lint              # oxlint (config: .oxlintrc.json)
npm run typecheck         # tsc -b
npm test                  # Vitest, run once; npm run test:watch to watch
npx vitest run src/content/schema.test.ts   # single file; -t "<name>" for a single test
npm run data:generate     # regenerate public/data/ from the seed
npm run content:status    # items per task/objective vs. target, with the kind mix
npm run content:quality [-- <file.json> ...]  # anti-giveaway checks, per file or whole bank
npm run content:links     # fetch every cited URL, lesson links included (needs network; not part of npm test)
```

Tests run in Node by default. Component tests start with `// @vitest-environment jsdom`. Vitest runs without globals, so `src/test/setup.ts` registers Testing Library's `cleanup`.

The `scripts/` run TypeScript directly in Node (native type stripping). So any `src/` module a script imports, and that module's own imports, must use explicit `.ts` extensions (`allowImportingTsExtensions` is on). The data modules and `content/schema.ts`/`quality.ts` already do.

To check a production build in a browser, run `BASE_PATH=/Tableau-DF_prep/ npm run build`, then `BASE_PATH=/Tableau-DF_prep/ npx vite preview`. Preview also reads `base` from `BASE_PATH`; without it, asset requests under the sub-path fall back to `index.html` and the page stays blank. Headless Chrome needs `--virtual-time-budget=30000` to wait for the lazy pages and the dataset.

GitHub Pages serves the app under `/Tableau-DF_prep/`. `.github/workflows/deploy.yml` runs lint, the tests and `BASE_PATH=/Tableau-DF_prep/ npm run build`, copies `index.html` to `404.html` so deep links work, and deploys on push to `main`. Vite's `base` and the router's `basename` come from `BASE_PATH`, so use router `Link`s, never root-relative `<a href="/…">`.

## Layout

- `src/content/blueprint.ts`: `EXAM_FORMAT` (format facts from the guide), `DOMAINS`, `TASKS` with their objectives **verbatim** (ids `"2.3"` and `"2.3.5"`, as the guide numbers them), `LESSON_ORDER` (concepts first: 4, 1, 2, 3), `largestRemainder`, `allocateMock()` (9 · 15 · 10 · 6), `TARGETS`/`questionTarget()` (600 items split by domain weight, then by objective count; at least `MIN_PER_OBJECTIVE` = 8), and `PUBLIC_LIMITS`.
- `src/content/schema.ts`: the Zod item union. All kinds share `id` (`<taskId>-NNN`), `taskId`, `objectives[]` (all under `taskId`), `stem`, `options` (`text`, `correct`, `rationale`), `explanation` and optional `sourceLinks`:
  - `single`: exactly 4 options.
  - `multi`: `select` 2–3, 5–6 options.
  - `viz`: `select` 1–3, 4–6 options, plus `viz: {spec, show: chart|shelves|both}` and optional `checks[]`: every Driftlight number or member the item states, as a lesson-style fact (`factSchema`, shared with lesson `meta.facts`).

  Multi-select stems must contain `(Choose N answers.)` exactly once, and single-answer stems must not. `selectCount()` gives N.
- `src/content/questions/<taskId>.json`: one JSON array per task, 600 items in all (346 `single`, 153 `multi`, 101 `viz`; every objective has at least 9), loaded by `bank.ts` (`ITEMS`, `QUESTION_FILES`). Tableau facts come from the task's lesson, which was checked against the help. `bank.test.ts` checks file/task match, objectives, unique ids, the `quality.ts` checks, and that every `viz` item draws over the data and states each `checks` value exactly as `evaluateFact` computes it. The checks cover single-answer items (`single`, and `viz` with `select` 1):
  - no key letter in more than 40% of items
  - the key is the strictly longest option in at most 40%
  - no duplicate stems (stem + viz spec)
  - explanations and rationales never cite option letters, so options can be reordered
- **Engine** (`src/engine/`). Engine modules import each other with `.ts` extensions, so scripts can use them.
  - `spec.ts`: the viz spec.
    - `source` is `sessions` (default), `subscribers` or `titles`.
    - `calcs`: the sheet's calculated fields `{name, formula}`, kept in the spec so `#spec=` links stay self-contained. Pills, filters and sorts name them like any field.
    - `fields`: Data pane edits of the source's fields, `{field (data source name), name?, type?, geo? (null removes), role?, as?, aliases?, agg?, format?, sort?, comment?}`, also kept in the spec. Everything else names a field by its current name.
    - `groups` (`{name, field, groups: {name, members}[], other?}`), `sets` (`{name, field, fixed?, rule}`; rule `members` (General tab or from marks, optionally `exclude`), `condition` (`{field, agg, op, value}`) or `top` (`{from, n, field, agg}`)), `bins` (`{name, field, size}`) and `hierarchies` (`{name, fields}`, general to detailed; a field is in one at most). Group and set members are underlying members' display strings.
    - `columns`/`rows` hold pills. The Marks card has `type`, `color`, `size`, `label`, `shape`, `detail[]` and `tooltip[]`.
    - `filters`: `values` (members by display string, optionally `exclude`), `range` (row-level, or a measure filter after aggregation when `agg` is set), `dateRange` and `datePart` (canonical numbers).
    - `measureValues`: the Measure Values card (pills), which the generated fields `Measure Names` and `Measure Values` (`MEASURE_NAMES`, `MEASURE_VALUES`) stand for. `axes: {columns?, rows?: {dual?, sync?}}`: Dual Axis on the shelf's two measures, and Synchronize Axis.
    - A pill is `{field, agg?, date?: {level, mode: part|value}, as?: discrete|continuous, sort?: {order, field?+agg? (computed), manual?}, mark?, setView?}`; `mark` is a measure's own mark type when its shelf holds several measures (its own Marks card). `weekday` can only be a part. Filters and manual sorts hold underlying members, before aliases. A set pill shows In/Out, or with `setView: 'members'` the members In the set.
  - `model.ts`: the field metadata (the dataset after preparation: Postal Code is a geo string, Release Year a discrete dimension, and Latitude/Longitude are measures with an AVG default) and `SOURCE_INFO` (fields in Data pane order, a `<Source> (Count)` measure, and `Latitude/Longitude (generated)`).
    - `buildDataset(csvTexts)` builds three flattened sources. Each base table is left-joined many-to-one to its lookups, so rows never multiply, and unmatched lookups become nulls. Sessions get titles, subscribers, plans and regions; subscribers get plans, regions and cancellations.
    - Values are typed: dates are UTC epoch ms and empty cells are null. `loadDataset()` fetches `public/data/` once in the browser.
    - Field edits: `fieldsOf` applies `spec.fields` before compiling calcs, so formulas see renamed fields; an edited field carries `original {name, type}`, and `calcsOf(ref).read` maps it to its column and converts the value (`convertValue`; `TYPE_CHANGES` lists the type changes offered, where the help's "Text is treated as Null" rules give the result). `isEditable` excludes calcs, groups, sets, bins, `(Count)` and generated fields.
    - Groups, sets and bins (`Field.derived`) are dimensions built on the edited source fields (never on calcs, and calcs can't use them); one with a missing or unfit field stays in the list with `broken`, and its pills turn red. `read` gives a group's name (or Other, or the member itself), a set's `In`/`Out` and a bin's lower limit (`binOf`, lower limit inclusive). `calcsOf(ref, rows)` takes the source's rows for sets with a condition or top rule, computed per member over the whole source (so filters don't change membership). `sheetOf(ref)` is the part of a spec that decides its fields.
    - Calculated fields: functions that take a field's source accept a `SourceRef` (a `SourceId`, or a spec-like `{source, calcs, fields}`); pass the spec wherever calcs or field edits may matter. `fieldsOf(ref)`/`fieldOf(ref, name)` add the compiled calcs (cached): a number calc is a measure (SUM), an aggregate calc a measure without a default aggregation (`AGG(…)`, `ResolvedPill.agg === 'agg'`), anything else a dimension. `calcFields()` keeps a broken calc in the list with `calc.error`, so the Data pane shows it and pills on it turn red. A calc may use the fields and the earlier calcs, never `(Count)` or generated fields.
  - `pills.ts`: `resolvePill` decides dimension or measure, blue or green, and the Tableau label (`SUM(…)`, `CNTD(…)`, `MONTH(…)`). It throws `EngineError`, which carries learner-facing messages.
    - Date dimensions default to the YEAR part (a YEAR value once the field is converted to continuous); a field's `as` sets the default continuity.
    - Aggregated numbers and COUNT/COUNTD are continuous, and MIN/MAX/ATTR of non-numbers are discrete.
    - Measure Names is a discrete dimension and Measure Values a measure without an aggregation of its own (`agg: 'agg'`, like an aggregate calc); neither can be aggregated, used in formulas or edited (`Field.special`).
  - `values.ts`: date parts and truncations (UTC, weeks start on Sunday), `display`, `compareKeys`, `aggregate`, and `formatNumber`/`formatExpr` (a field's number format in JS and as a Vega expression), shared by the query layer and the calc evaluator (`query.ts` re-exports them).
  - `calc/`: the calc subset (PLAN.md §7b), data-free except `run.ts`/`runtime.ts`.
    - `syntax.ts` tokenizes and parses (the help's precedence table; `CalcError` has `kind` syntax|field|type|mix, a `span` and an optional `explain`). `check.ts` gives every node a type and a level (row, agg, const) and throws Tableau's verified message `MIX_MESSAGE` ("Cannot mix aggregate and non-aggregate arguments with this function.") when they mix. `functions.ts` holds the function table (syntax, summary and an example from the help, type rule, implementation) and the date helpers; `evaluate.ts` runs a node in a row scope or a group scope. Null and divide-by-zero rules follow the help and the Tableau KB; where the help is silent (ROUND halves, SPLIT out of range, CONTAINS case, month-end DATEADD, `/` on integers), the code says so and no exercise depends on it. `TODAY()` is pinned to `CALC_TODAY`.
    - `index.ts`: `compileFormula`, `rowValue`, `evaluateRow`, `evaluateGroup`. `run.ts`: `previewCalc` (sample rows, or one row per member for an aggregate calc) and `checkCalc` (compares a formula with a reference over every row, or per member of the exercise's `by`, and phrases the first difference). `runtime.ts` is the playground's lazy chunk (dataset, no Vega).
    - `calc.test.ts` runs the help's examples, the null rules, precedence, the errors, and calcs in queries against plain reductions.
  - `query.ts` (`query(spec, dataset)`) runs: row filters → one group per combination of the view's dimension members → aggregation → measure filters → member order. Results are `{columns, rows}`, keyed `c0, c1…`.
    - Discrete members are display strings (`Q3`, `January`, `Null`, `True`). Continuous dates are epoch ms.
    - Each discrete column carries its member `order`: the natural order (date parts chronologically, strings alphabetically, Null last), a computed sort, or a manual one; a pill's sort wins over the field's default sort. Aliases apply last: `order` and the rows hold the aliases, `raw` the underlying members.
    - Generated coordinates come from the finest geographic dimension in the view, using `data/geography.ts`.
    - With Measure Names or Measure Values in the view, each mark also computes the Measure Values card's measures (less those a Measure Names filter leaves out), and the rows unpivot: one per mark and measure, Measure Names ordered as the card.
    - `columnOf(result, source, pill)` reads a pill's column. Use it in tests and checkpoints instead of assuming column order, because columns follow `pillsOf` order: Columns, Rows, then the Marks card.
  - `render.ts` (`toVegaLite`):
    - The innermost pill on a shelf becomes the axis (continuous) or the band (discrete). The discrete pills before it become facet panes, several joined with " · ". Several continuous pills at the end of one shelf (one shelf only) become measure panes: the measures fold into `__v` with a `__m` pane each and independent scales, one layer per mark type. With `axes[shelf].dual` the two measures layer in one pane with an axis each (independent scales, or shared when synchronized), coloured from `DUAL_COLORS` when Color is empty.
    - `automaticMark` follows Tableau's Automatic (the help's rules, lesson 2.1/3.1): geo → circle, nothing continuous → text ("Abc" without a label), a date field (part or value) with a measure → line, measure × measure → shape, a continuous dimension × measure → circle (no documented rule), otherwise bar. Each measure's mark is its own `mark`, else the Marks card's, else Automatic's for its pair of axes.
    - A continuous number column whose field has a `format` gets a `labelExpr` axis and `<id>f` text columns for tooltips and labels.
    - `square` on two discrete shelves becomes a highlight-table `rect`. `density` uses translucent circles. `map` draws a filled country map via a lookup on world-atlas ISO ids; lat/long marks draw on an `equalEarth` world.
    - Band width comes from the longest label. Charts take colours from a `Theme`. `needsWorld(spec)` says whether to load the topology.
  - `edit.ts`: pure spec edits for the sandbox (`placePill`, `movePill`, `removePill`, `replacePill`, filters, mark type), the pill-menu rules (`aggregationChoices`, `withAggregation`, `withDateLevel`, `canToggleContinuity`, `withContinuity`), `defaultFilter`, and the `#spec=` hash (`specHash` writes it without defaults, `parseSpecHash` reads it). Shelves are addressed as `PillAt {shelf, index}`; Color/Size/Label/Shape hold one pill, so a drop replaces. `setCalc` adds or replaces a calc (a rename follows through pills, filters, sorts and formulas), `removeCalc` takes its pills and filters with it. `editField(spec, original, patch)` changes a field (`undefined` keys go back to the source; a rename follows through like a calc's and throws `EngineError` on a taken name; a new type clears the field's filters and its pills' date levels and sorts), `resetField` undoes all of it. `combineOnAxis(spec, shelf, field)` drops a measure on a shelf's axis (Measure Values on the shelf, both measures on the card, Measure Names on Color when free); `setDualAxis`, `setSyncAxis`, `setPillMark`, `continuousOn`. The Measure Values card is a list shelf (`measureValues`). `setDerived(spec, 'groups'|'sets'|'bins', index?, def)` adds or replaces one (a rename follows through; a taken name throws), `removeDerived` takes its pills, filters and hierarchy place with it. Hierarchies: `createHierarchy`, `addToHierarchy`, `removeFromHierarchy`, `removeHierarchy`, and drilling on a list-shelf pill (`drillState`, `drillDown` puts the next level right after it, `drillUp` removes the levels below).
  - `match.ts`: `matchSpec(spec, accepted[])` for challenges, data-free. Pills compare by resolved key, the mark by its effective type (Automatic resolved), Detail unordered, Tooltip ignored, filters as sets, sorts only where the target has one. Hints come from the closest accepted spec.
  - `runtime.ts`: a lazy chunk with the dataset, query, vega-embed and world-atlas. `membersOf(source, pill)` lists members for the filter, alias and manual-sort dialogs: labels with aliases, values underlying (date parts carry their canonical number, via `partFromLabel` in `query.ts`). It uses only `sheetOf(spec)`, never its shelves or filters. `renderViz(el, spec, theme, onMark?)` reports a clicked mark's discrete dimension members (underlying values) for groups and sets made from marks; `<Viz onMark>` passes it through. `Viz.tsx` imports it on first draw, keys its state by the spec's JSON, and shows `EngineError` messages. `Shelves.tsx` and `PillChip` show a spec's shelves read-only and need no data.
  - Tests: `src/test/dataset.ts` gives `testDataset()` (the committed CSVs) and `referenceData()` (the generator's typed rows, the independent reference). `query.test.ts` checks the engine against plain reductions over the reference. `render.test.ts` compiles every chart type with Vega-Lite and renders it to SVG in Node (`new View(parse(compile(vl).spec), {renderer: 'none'}).toSVG()`).
  - `src/pages/ChartGalleryPage.tsx` (`/dev/charts`, not in the nav) shows each basic chart type from the outline with its shelves. Use it to check rendering in a browser.
- **Dataset** (`src/data/`):
  - `generate.ts` builds the Driftlight dataset from `SEED`: 3,000 subscribers, 4 plans, 400 titles, 15k sessions in 2024 and 17k in 2025, about 400 cancellations, 25 countries in 5 regions, and monthly targets by region. It returns the file contents plus the typed rows.
  - `scripts/generate-data.ts` writes the files to `public/data/` (committed, served for download). Changing the generator moves every number the content cites.
  - `data.test.ts` fails if the committed files differ byte for byte from the generator. It also checks consistency (sessions only by active subscribers, of released titles) and the deliberate quirks:
    - ZIP codes with a leading zero
    - city spelling variants (München/Munich, Köln, Sao Paulo, Bogota)
    - a few null `Minutes Watched` and blank `Device` values
    - union-compatible session files
  - `xlsx.ts` is a minimal deterministic `.xlsx` writer (fflate, fixed local-time mtime) for `targets.xlsx`. Monthly dates are stored as real Excel dates.
  - `rng.ts` holds `seededRng` (mulberry32), `pick`, `weighted`, `randInt`, `shuffle` and `sessionRng()` (a generator seeded from `crypto`, one per practice session or mock). Never use `Math.random` for content or samplers: samplers take an `Rng`, and tests pass a fixed seed.
- `src/data/geography.ts`: the regions, countries (with ISO numeric ids for world-atlas) and cities with coordinates. Both the generator and the engine use it.
- **Quiz** (`src/quiz/`):
  - `grade.ts`: a `Response` is the list of chosen option indexes, for every kind. `grade` is all or nothing; `isAnswered` means exactly `selectCount(item)` picks.
  - `weights.ts`: `TASK_WEIGHTS`, each domain's weight shared among its tasks by objective count (the same split as the bank targets). Practice, readiness and mixed sets weigh by task.
  - `sampler.ts`: `buildMockExam(bank, seen, rng)` takes each domain's `allocateMock()` share, splits it among the domain's tasks by objective count, makes up a short task from the rest of its domain, puts seen items last, and scales the minutes to the real pace when the bank is short. `buildMixedSet` (weighted by task, not pool size), `buildFocusSet` and `orderLeastMastered` (lowest streak first).
  - `results.ts`: `scoreMock` (percent, pass at 48%, rows per domain and per task) and `taskRows`.
  - `ItemView.tsx` renders every kind: a `viz` item draws `<Shelves>` and/or `<Viz>` per `show`. Revealed, it shows each rationale, the explanation, `sourceLinks` and the objectives. `showTask={false}` hides the task name (the mock does). `SessionReview` mounts an item only when its row is opened, so closed rows draw no charts. `shortcuts.ts` (`useShortcuts`), `ShortcutHint`, `ScoreTable`.
- **Progress** (`src/progress/`): `store.ts` (above, version 5) keeps item stats with a streak, mock results, sandbox challenge completions (`sandbox`: id → first solve time), `lessonsRead`, calc exercise completions (`calcExercises`) and saved calcs (`calcs`: `{source, name, formula, savedAt}`, unique per source and name), flashcard review state (`flashcards`: card id → `{box, due, lastAt}`) and own decks (`decks`: `{id, name, cards: {id, front, back}[], createdAt}`; card ids `my-<uuid>`, and removing a card or deck drops its review state), with export and import. `migrate()` upgrades v1–v4 data both on load and on import. `readiness.ts`: `taskReadiness` (coverage × accuracy), `weightedReadiness`, `weakSpotItems` (the 3 weakest tasks) and `masteryOf`/`MASTERY_LEVELS`.
- **Sandbox** (`src/build/`): `Sandbox.tsx` (Filters, Marks card, Columns/Rows, the view with the marks selection bar (Group, Create Set), and the open dialog; it edits a spec the page owns), `DataPane.tsx` (fields by role, hierarchies as trees, field menus; a dimension dropped on a dimension adds it to that one's hierarchy or starts a new one), `DerivedEditors.tsx` (Group, Set with General/Condition/Top tabs, Bins, Create Hierarchy), `ShelfPill.tsx` (pill and its menu, the drill +/− button, Show In/Out of Set or Members in Set, Dual Axis and Synchronize Axis on a shelf with two measures); the Marks card shows a tab per measure (All, then each) when a shelf holds several, and the Measure Values card appears when it's in use; a measure's Data pane menu offers Drop on the Columns/Rows axis, `FilterEditor.tsx`, `SortEditor.tsx` (members, field or Manual with Move up/down; for a pill or, with `scope="default"`, Default Properties > Sort), `FieldEditors.tsx` (Rename, Aliases, Comment, Number Format dialogs), `members.ts` (`useMembers`, `manualKey`), `Menu.tsx` (accessible menu button: arrow keys, Escape, focus return), `dnd.ts` (HTML5 drag and drop; every drag also has a menu path, which the tests use). `CalcEditor.tsx` (name, formula, live `CalcStatus` with the error span marked and a lesson link, field and function lists that insert at the cursor; `calcStatus()` compiles a formula on a sheet) is shared by the playground and the sandbox's calc dialog. The Data pane lists the sheet's calcs (`=` icon), creates and edits them, and adds saved ones; applying a calc there also saves it. Each base field's menu has the lesson 1.3/4.2 actions (Rename, Aliases, Convert to Dimension/Measure and Discrete/Continuous, Create Group/Set/Bins, Change Data Type, Geographic Role, Default Properties: Comment, Number Format, Sort, Aggregation), every dimension's has Create/Add to/Remove from Hierarchy, and a sandbox-only "Undo all changes to this field"; the comment shows as the field's tooltip.
- `src/content/calc.ts` + `calc/<taskId>.json` (the task of the first objective): the calc exercises (`id` is stored in progress, never rename; `name`, `prompt`, `fields`, the reference `expected`, `by` for aggregate ones, `accepted` and `wrong` formulas, `hints`, `debrief`). `calc.test.ts` checks that the reference compiles, uses exactly `fields`, gives more than one value, that `by` is set exactly for aggregate formulas, and that every `accepted` formula passes and every `wrong` one fails. - `src/content/flashcards.ts` + `flashcards/<taskId>.json`: the built-in cards (`id` `<taskId>-cNNN` is stored in progress, never renumber; `objectives`, `kind` term|menu|file|recipe|rule, `front`, `back`; 287 cards).
